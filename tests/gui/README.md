# GUI verification suites

Checks for the browser-based viewer in `gtrace/draw/viewer/` and the
`OpticalLayout` model behind it.

```
pixi run python tests/gui/run_all.py
```

That runs everything in dependency order and prints a summary. A single
suite can be run on its own once an earlier run has left its inputs in
`_work/`.

Everything the suites generate goes to `tests/gui/_work/`, which is
ignored by git and safe to delete.

## Requirements

- **Node.js** for `verify_stage1.js`, `verify_input.js` and
  `verify_rect.js`, which load `viewer.js` directly.
- **A Chrome-like browser** for the browser suites, found automatically
  or named through `GTRACE_CHROME`.

Both are optional: a suite that cannot run says so and `run_all.py`
counts it as skipped rather than passed.

## What each covers

| `verify_beam.py` | A beam's width, reduced q and circular q **agree with the q it was given**, over q-parameters that include the trait's own default. Traits does not notify when an assignment matches the value already there, so `GaussianBeam(q0=1j)` used to keep a reduced q of zero and come out of its first propagation with a real q. Also the same invariant after propagating, in glass, through `copy()`, and over every beam a trace produces. Then what `copy()` itself promises: every field carried over, the class kept, arrays duplicated and everything else shared, an attribute added by hand coming along, and the copy still a live object - handlers run on it and it still refuses a value of the wrong type |
| `verify_geometry.py` | The geometry kernel every hit test and every drawing goes through, now that it is written on plain floats rather than numpy arrays. The two intersection routines against a circle and a line **worked out in the suite rather than taken from them**; `vector_rotation_2D` over both of its paths, including the shapes the drawing code sends - (2, 60) for an arc, (2, 100) for a beam outline - and the nested list that the fast path has to decline; and `_surface_matrices` giving **nan transmission past the critical angle**, which is how a caller tells total internal reflection from a refraction, with reflection still a number. Also every matrix having determinant 1, and a flat interface crossed both ways being the identity |
| `verify_surfaces.py` | Where the two faces of a substrate are, against an arc derived independently of the class: both curvature signs, both faces, at four heights across the aperture, plus `isHit` agreeing with what `hitFrom*` then traces, and the drawn arc meeting the drawn sides. Then the bounding circle `isHit` rejects beams with: swept across its own boundary from 26 directions on eight substrates, it must never reject a beam that the four faces say hits, and must reject every one that passes wider than the radius |
| `verify_lens.py` | `Lens`: for seventeen lenses, the focal length **measured by tracing a ray through them** and reading the angle it leaves at, which owes nothing to the formula the constructor solved. Also what the constructor refuses and why, the defaults a lens needs, copy and save/load, and that a lens does not turn the beam through it into a ghost |

| `verify_stray.py` | What a stray order is and what `order` caps, two numbers with similar names that have been confused twice here. A stray order rides with a beam and counts what it has already done that an element was not built for; `order` is the budget for making new ghosts, not a test the arriving beam has to pass. Also **what `term_on_HR` stops**: the whole beam, or - with `term_on_HR_transmits` on - only the external reflection that would form the cavity, leaving the substrate crossed, the transmission followed, and the ghosts inside it capped by `order` and `max_stray_order` like any others. And that all three settings can be given to the constructor, survive a save and load, and survive `copy()`, which used to rebuild an element from `term_on_HR` alone |
| `verify_dimensions.py` | Substrate corners against `get_side_info`, what a span runs inside (`contains_segment`, including the hollow of a concave face), the snap points - including the middle of each side of a substrate, and that a **curved face is offered none**, since the middle of its chord is inside the glass - and the `Dimension` model through the edit protocol |
| `verify_rect.py` | A rectangle that is **turned**: its corners against the rotation written out by hand, both signs and past a half turn, the pivot it was given and the middle it uses when it was given none - which is worked out rather than written down, so a rectangle that is carried keeps turning about itself. Then everything downstream that has to agree about where it is: the bounding box, the middle, `turned_shape` carrying one and turning one, a body's world shapes and what its outline holds, serialization both ways (**a file written before there was an angle loads square to the axes**), the DXF written through the corners it really has, and the editor protocol setting an angle and a pivot and refusing a nan. Also that **nothing square to the axes moved**: a breadboard writes the same plate it always did |
| `verify_rect.js` | The page and gtrace agreeing about where a turned rectangle is. Both work its corners out for themselves - Python to draw, bound and export it, `viewer.js` to draw, pick and drag it - so the numbers `verify_rect.py` writes are held against `rectangleCorners`, the bounds, the snap points, what a click falls inside, what a turn of the whole part previews, and what the panel rows read and send. | `verify_rect_browser.py` | Headless browser: **where a turned rectangle is actually painted**. ## Two things these suites learned the hard way

**Drive the entrance the framework uses, not the internals.** The Stage
2b checks called `apply_edit` directly. Ninety-one of them passed
against a widget that could not receive a single message, because the
handler had been given a name that shadowed ipywidgets' own dispatcher.
`verify_stage2b.py` now sends a real comm message through
`Widget._handle_msg`.

**Drive every output path separately.** The read-only viewer was
exercised through the widget's ESM with a scene from `scene_dict`. That
reproduces "no Python behind the page" but never the scene the static
file actually carries - so the static HTML shipped without its optics
channel, and clicking a mirror in it did nothing. `verify_browser.py`
now opens the file `renderHTML` wrote and clicks a mirror in it.

## The tutorial notebook

```
pixi run python tests/gui/run_notebook.py
```

Executes `docs/source/tutorial/gtrace-tutorial.ipynb` in place. This is
the only check that runs the documented code end to end, so an example
that has drifted away from the library turns up here rather than in a
reader's session.

It then removes three things that would otherwise change on every run
for reasons that have nothing to do with the notebook: the saved widget
state, which embeds a copy of `viewer.js`; the widget outputs, whose
text is an object repr carrying a memory address; and nbconvert's
per-cell wall-clock timings. Consecutive stream outputs are joined, since
where the flushes fell is not information either.

The result is reproducible: run it twice without changing anything and
the file does not change, so a diff against it means something real did.
